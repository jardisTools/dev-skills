#### 2.4 Queries

Door: MCP `save_queries`, `validate_queries`, `preview_queries`, `probe_query`, `save_query_layout`, `rename/delete/duplicate_query`; resources `queries`, `queries/catalog`; UI queries surface. BC-wide `Queries.json`. Every query is a paginated list; the answer is always `{items, total, limit, offset}`.

| Setting | Allowed values | Effect |
|---|---|---|
| Base list `{agg}List` | seeded once per aggregate on first save, editable afterwards | the list every aggregate has; rules and process nodes read counts and keys through it |
| `root` | an entity of the own BC; only a query rooted on the aggregate root has a door row (a query on a child entity is always `closed`) | owning aggregate |
| `name` | PascalCase stem | its class stem must not equal `{Agg}{ById\|ByIds\|By<Key>\|By<Key>s}` of the emitting aggregate (a derived read way): blocker V-QDEF-26 instead of a silent first-wins |
| stance (no key in `Queries.json`: the row of the query in the block of its root entity in `Doors.json`) | `closed` (default) / `domain` / `outside` | `domain` becomes a read method on `{Agg}Read` for the BCs of the domain; `outside` also an API route and a right (needs `limit`). A query that reads inward (`closed`/`domain`) is the only read that projects `writeOnly` columns. A `visibility` key in `Queries.json` is retired (V-DOOR-0) |
| `limit` | int, mandatory | cap on the page size (above 500 warns); paging continues |
| `joins[]` | `entity` (own BC, also across aggregates), `as`, `type` (`inner` `left` `right` `full` `cross`, no default), `on` (optional inside the root aggregate, mandatory beyond; `on.and` adds further field pairs, AND-connected, for a composite key) | joined fields usable in `where` as `alias.field`; list order matters; `full` fails on MySQL and SQLite |
| `parameters[]` | `name`, `type` (`string` `int` `float` `decimal` `bool` `date` `list`; `decimal` and `date` travel as `string` in the signature), `optional`, `default` | bound filter arguments; optional → nullable argument; names `limit`/`offset` are reserved |
| `where` | tree of `all:` (AND) / `any:` (OR); leaf `field` + `op` + `value` | fields, never columns (the field map translates). The query key `chain` (`{via, from, to, start, maxDepth}`, optional `where`, `key`, `depthParam`) restricts the root rows to those a bounded recursive walk reaches (a tree in one table, or an edge table); a pure filter, the answer stays the paginated list; `maxDepth` 1..999 measures the shortest path; needs `jardissupport/dbquery` >= 1.3.1; blockers `V-QDEF-33`, `V-QDEF-34`; form: `design-headless-mcp` |
| `op` | `equals` `notEquals` `greater` `greaterEquals` `lower` `lowerEquals` `like` `notLike` `between` `notBetween` `in` `notIn` `isNull` `isNotNull` | `contains`, `length`, `exists`, `notExists` are rejected (V-QDEF-7); text search is `like`. `like`/`notLike` take an optional `match`: `pattern` (default, same as no `match` — the caller supplies the finished pattern) · `contains` · `startsWith` · `endsWith` · `literal` — the four literal modes read the value as a search term (`string` parameter or string constant) and the generator emits `LikePattern::<mode>($term)` from `jardissupport/dbquery`, so `%`, `_` and `\` in the term (e.g. `50%`) count literally. `match` on any other operator is a blocker (V-QDEF-27) |
| `value` | `{param}`, `{const}`, `{user: true}`, `{from,to}`; none for `isNull`/`isNotNull` | a leaf bound to an optional parameter is skipped when the argument is absent. `{user: true}` is the id of the signed-in user, bound from the request context (never from the client, no parameter at the outer door); single value or range side, never in `in`/`notIn`; exactly one of the three value kinds per leaf; in a world without login the blocker `V-TENANT-3`. See "My records" below |
| `orderBy[]` | `field`, `direction` | the root PK is appended as tie-breaker automatically |
| `total` | count of matching rows ignoring paging | counts JOIN rows: a join to a `many` child can count one root several times — check with `probe_query` before relying on it. On a root with `access` and a filter in force the count stops at a cap (the constant `AclFilter::COUNT_CAP` of `jardissupport/acl`): above it `total` carries the cap and the envelope has `capped: true` (absent otherwise); a declared `limit` above the cap is the blocker `V-ACCESS-7` |
| "My records" (a plain query, no feature) | an ordinary query whose condition compares a column of the root, chosen by the modeller, with the value `{user: true}`: `{"queries": {"DocumentsCreatedByMe": {"root": "document", "limit": 50, "where": {"all": [{"field": "document.createdBy", "op": "equals", "value": {"user": true}}]}, "orderBy": [{"field": "document.createdAt", "direction": "desc"}]}}}` | Jardis does not define what "mine" means (created by, assigned to, owner: the column is the modeller's choice) and generates no such list itself. Delivered like any query (a stance `outside` row in `Doors.json` gives route and right; the door has no user parameter, the value comes from the session). On a protected aggregate (protection is the rule, see `access`) the sight acts in addition, as on every other delivered query: the list shows the records that match the condition AND that an entry of the caller's groups makes visible |

**2.4a Door stances (`Doors.json`).** Door: MCP tool `save_doors`, resources `jardis://doors/{domain}/{subdomain}/{bc}` and `jardis://doors/{domain}`; UI door table in the API row of the BC page. BC-wide `Doors.json`, one row per door, written by the builder, changed by the human or by the AI through `save_doors`. Stance of a row: `closed` (own BC only) · `domain` (facades of the other BCs of the domain; no route, no right) · `outside` (route, OpenAPI path, right; session + right) · `open` (no login, no right; process rows only — anything else is V-DOOR-0). Rows: one block per aggregate (read ways `{agg}ById`/`{agg}ByIds`, with a public unique key only `{agg}By{Key}`/`{agg}By{Key}s`; base list `{agg}List`; declared queries of the root entity; commands by class name, `Create{Agg}` …) and the block `process`; the row is named like the facade method. Defaults without a row: read ways and base list `outside`, declared query `closed`, command `closed`, process `outside`. A row that names no door is the warning V-DOOR-1 (remove it with `save_doors` `remove`); the build never deletes a row.
