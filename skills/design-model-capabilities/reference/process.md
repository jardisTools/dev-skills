#### 2.5 Process

Door: MCP `create_process`, `save_process` (whole process wire), `validate_process`, `update_process_metadata`, `build_process`, `regenerate_process_node`, `rename/delete/duplicate_process`; resources `processes/…`, `process-library`, `process-edge-status-catalog`; UI process designer. A process is the outer door of a write: one process = one endpoint. Optional root key `access: {aggregate, keyFrom, level}` (`level` ∈ `view` `edit` `all`; omit = keep, `{}` = delete): the door asks the access check once before the run for the record of `aggregate` that the input field `keyFrom` names (no sight 404, level too low 403 `forbidden`; no node runs, no transaction); blockers `V-PROC-ACCESS-1` to `-3`, warning `-4` at the stance `open`; exact form: skill `design-headless-mcp`.

| Setting | Allowed values | Effect |
|---|---|---|
| `kind` / `runInTransaction` | `command`\|`query` / bool | endpoint path; transaction bracket. The stance of the process is its row in the block `process` of `Doors.json` (default `outside`): `closed` = no facade method, only a sub-process target of the own BC; `domain` = facade method `{BC}Process::{name}()`, no route; `outside` = route + right; `open` = route without login or right. `visibility` and `subprocessOnly` are retired (V-DOOR-0) |
| `input.fields[]` | scalar (`type` from the column-type vocabulary of the aggregate door, e.g. `varchar` `int` `decimal` `bool` `date` `datetime` `uuid` `json`, or a named `valueList:`; `enum` is no scalar; `string`, `array` and `mixed` are legacy words, `array` and `mixed` warn V-INPUT-UNTYPED; a list is `list: true` with the element type; plus `default`, `nullable`) or command field `accepts: ["Agg.Command", …]` (+ `list`) | request contract as a discriminated union over the accepted commands; accepted commands can be root commands AND child commands (`Contact.AddContactOrganization`). No input field takes a request attribute (`requestAttribute` is no format term any more); tenant and user are no declared input: the door fills the fields `tenant`/`user` of the process input in a world with login, a node reads `$ctx->input()->tenant` / `->user`, and a Rule node on a tenant-marked root takes its scope from there, no input field needed |
| Node = action | `consumedCalls[{facade, method}]` (identity = Command key: dtoType, else method, first letter normalised) on the aggregate facade (command or read) | calls the generated command, no body to write (the answer is the callee's, typed through `MapResponseInto`, a 4xx becomes a `reject`); `dtoShape` declares the call's input shape, `gives: {kind, name, …}` says what the node hands out (see the row `gives`); the key `response` is a load error (CUT1) with the migration hint |
| Node = rule | `rule: <Closure name>` + either `ruleSubject.payloadField` (short form: closure with exactly one command/aggregate input) or `ruleArgs[{param, source}]` (long form: EVERY closure input exactly once; never both, V-PROC-RULE-ARGS) | calls a catalog closure inside the flow; should not also be bound at the endpoint chain of the same command (V-RULE-NODE-DOUBLE-BIND warns: the rule would run twice, drop one binding). `source` = a process input field name, or `{kind: latest, node, field}` = a field of the latest result of an earlier station (command node: `facade`+`method` too; hand-written node: a member of the object value it `gives`); no `all`. A subject that cannot be loaded is 404 `{bc}.{agg}.notFound` in guard and in decision mode (`ruleMode`), never a verdict: only a refusal by the rule is 422 and, in decision mode, routes `onFalse` |
| Node = sub-process | `subProcess: <process>` in the same BC, not itself | synchronous delegation |
| Node = cross-BC call | `crossBcCall: <service name>`, target `consumedCalls[0]` in ANOTHER BC; writes only via a door of the foreign BC at `domain` or wider (its `process()` or a command door; `V-CONSUMED-EXISTS`) | service stub + DTO translation |
| Node = external call | `externalCall {service}` (there is no `level`) | call outside the workspace via a Domain Service stub at `{BC}/Service/` of the calling BC, the one place (`generated-code-extend` §10) |
| Node = event | `mode: async` + `eventFields[]` (`source` = input field, or collector `{kind: latest\|all, node, facade, method}`; `label`) | event record built from named fields; transport recipes in `generated-code-recipes` |
| `mode` | `sync`\|`async`, mandatory per node | |
| `edges[]` | `from`, `on`, `to` or `terminal: true`; `on` ∈ `onTrue` `onFalse` `onTimeout` `onSkip` `onCancel` `onExit` (the pre-3.0 edge words are load errors with a rename hint) | routing only — an edge carries no data, no status and no message key. A refusal is no edge: a 4xx is a `reject` of the node (a call node hands the callee's 4xx on through `MapResponse` / `MapResponseInto`) and ends the run, a 5xx is an exception (500). `onFalse` is the No route of a question (a decision rule, or `Route::OnFalse` from a dev body — V-PROC-ROUTE-UNDECLARED warns when a body returns a route with no edge; a guard rule node declares no `onFalse`, V-NODE-GUARD-ONFALSE) |
| `rejects[]` (per node) | `{status, messageKey}`, status 4xx only (V-NODE-REJECT-STATUS, load error); `messageKey` = `{bc}.{cause}` | the node's own 4xx answers: they enter the OpenAPI contract and the interface board and give the reject its message key. A dev body that rejects with a literal status its node does not declare is the blocker V-NODE-REJECT-UNDECLARED. A hand node that declares `rejects` 400 to check the content of an input field itself is the warning V-PROC-DUPCHECK: `subject.fields` names the fields Jardis already checks (duplicate), empty means the wrong form — presence is 400 `missing` at the door, a condition is a Rule answering 422. `responses[]` on a node or edge is a load error with a migration hint. A 422 of a Rule node comes from the Rule contract; the process gate's 400 lists one finding per field with `messageKey` `validation.missing` / `validation.invalid` |
| `gives` (per node) | `{kind: aggregate\|identifier\|value\|nothing, name, aggregate?, many?, type?, fields?[{name, type, nullable?, list?, ref?, rowsOf?}]}` — every node of a process declares it, also `nothing` (V-PROC-GIVES-1); `name` is the entry of the process map (one name = one kind and type, V-PROC-GIVES-3); `value` is a scalar `type` or an object with `fields` (type from the `Schema.json` column vocabulary) | what the node hands to later nodes and to the answer: it becomes the typed getter `$ctx-><node>()` of `{Name}Context` and, for an object value, a generated `final readonly` class; the kind must fit the node form (V-PROC-GIVES-2); set through the Process Designer or `save_process` |
| end node (`gives` / `ref`) | an end node is every node with a terminal edge `{from, on, terminal: true}` on a non-failure status; its `gives` IS the 200 answer of the process, one form per exit; `gives.name` is mandatory here (also `nothing`) and is the outcome name, delivered as `@outcome`. Field of a `value`: `{name, type, nullable?, list?, ref?}` — `ref` (`<Agg>` own, `<Subdomain>.<BC>.<Agg>` foreign) marks a reference to an aggregate root the process wrote, `list: true` a list | declares the 200 `data`: `@type` + `@outcome` (the `gives.name` of the end node that ran) + the fields of that end node (identifier: the reference value of its command; nothing: `@type` and `@outcome` only); outcome name: `^[a-z][A-Za-z0-9]*$`, at most 64 characters (V-PROC-OUTCOME-2), the same name at two end nodes only with an identical inner form (V-PROC-OUTCOME-1); every aggregate a writer on the success path writes needs a `ref` field at the end node (V-PROC-ANSWER-1…3, 5, 6); outside the owner a `ref` field is left out when its aggregate has no read door in the reader's world (neighbour BC: `domain`, HTTP: `outside`); typed in the OpenAPI (`x-jardis-response: reference` / `fields`, several outcomes as `oneOf` + `discriminator` on `@outcome`, one outcome as `$ref`); `generated-code-recipes` Recipe 6. The keys `end`, `successOutput`, `answer` and a node `response` are load errors (CUT1) naming their replacement |
| `reads[]` (action node) | `{query, needs: statusFilter\|dateInterval\|identifierChain, binds}`; `query` is a declared query of `Queries.json` or the read base of an own-BC aggregate (`{agg}ById`, `{agg}ByIds`, `{agg}By{Key}`, `{agg}By{Key}s`) | declared read of an own-BC query; a body that reads a query the model does not declare (or a handler of another BC) is the warning V-PROC-READ-UNDECLARED, a declared read the body never makes a suggestion |
| `description` (process and node), node `purpose`, `acceptanceCriteria[]` | text | the process `description` becomes the docblock of the process facade method, the handler and the node classes; a node `description` becomes the docblock of its node class. `purpose` and `acceptanceCriteria[]` are kept in the definition but reach no stub — put what the AI must know into `description` |

Cycles are allowed only with an exit; unreachable nodes, dangling edges and a missing or unknown `start` are rejected by validation.
